# LIN-4570 findings (copied from the ticket comment, 27 Nov 09:12Z)

**Spike findings (macOS 27.0.1, kitty 0.47.4).** Everything ran in my own kitty instance (own socket and instance group). The live dispatcher kitty was only read through WindowServer's window list. Nothing in simple-dispatcher was changed.

**1. Can ghosts be detected? Yes.** `CGWindowListCopyWindowInfo(kCGWindowListOptionAll)` still lists them, and it can be called from a shell with no Xcode through JXA (`osascript -l JavaScript`, `ObjC.import('CoreGraphics')`). A ghost is a window still owned by the kitty PID with **bounds 0×0, alpha 0 and onscreen=false**, keeping its last title. `kitty @ ls` no longer shows it. That 0×0 frame is what kitty's own workaround leaves (it zeroes the frame before closing).
- Reproduced: closing my instance's first, `--start-as=hidden` OS window left exactly that entry (`win=877 alpha=0 name="zsh" 0x0`). `kitty @ ls` was empty while WindowServer still held it, and it was still there more than 30 min later.
- Don't confuse ghosts with kitty's fixed helper windows. Those are also 0×0 or 1512×30, but have alpha 1 and no title: 3 at startup, plus 5 more on the first `launch`.
- Check: `grep -c 'alpha=0 .*0x0'` over that list, filtered to the kitty PID. It's cheap enough to log as a metric. The live instance shows 0 ghosts right now (it restarted at 08:03 and no session has closed since).
- Not reproduced: the build-up itself. With the display on and this user switched out (the console belongs to `work`), 40 `--dont-take-focus` OS windows, a tab-created OS window and 30 tabs all closed with nothing left behind. The display stayed on for the whole spike (07:57 → 09:08), so the display-off case (pmset shows it off most of each day, e.g. 15:05 on 25 Nov → 12:21 on 26 Nov) is **still untested**. Next step: leave the probe at `<scratchpad>/tools/probe.zsh` running overnight against a throwaway kitty, and confirm display-off ghosts have the same signature.
- The ghost from the hidden window (closed at about 08:15) was still listed at 09:08.

**2. Tabs in one window? Yes, easily and reliably.** In my instance I launched 30 sessions with `kitty @ launch --type=tab --match id:<anchor tab> --dont-take-focus /bin/zsh -l -c …` and closed them three ways: 8 with `close-window --match id:N`, 7 with SIGTERM to the process group (the dispatcher's backstop path) and 15 by their own process exiting. Every tab got a real PID through `ls --match id:N`, and `get-text` worked on background tabs. **The WindowServer count stayed at 9 throughout**, because tabs aren't macOS windows. The same test with 30 `--type=os-window` launches showed +2 WindowServer windows per session while open, all released on close (display on).
Edge cases: if the anchor tab is gone, `--match id:1` fails with `No matching tabs for expression: id:1` (exit 1). Plain `--type=tab` with no `--match` lands in the instance's only OS window. With zero OS windows it creates one. So the only window that can be closed, and leave a ghost, is the anchor, and only if it's ever closed.

**3. What would change? About 1 line plus a test, roughly half a day including a pilot.**
- `terminal-driver.js:1176`: change `--type=os-window` to `--type=tab`, optionally with `--tab-title <sessionId>`. Leave `--match` off so a lost anchor can't fail a launch; the hidden `-1 --instance-group` window from `openKittyInstance` (:1052) then holds every tab.
- No other change needed: `closeWindow` (:1130 plus the SIGTERM backstop), `capture`/`get-text`, the PID poll (:1217), `countWindows`/`countKittyWindows` (already counts windows across tabs) and the signal guard all worked unchanged on tabs in this test.
- Update the architecture comment (:886-892) and add one unit test that asserts the launch arguments (none asserts them today; `test/terminal-driver.test.js:500` and `test/feedback.test.js:165` only mention os-window in comment or fixture text).
- Optional: an env flag such as `SD_KITTY_LAUNCH_TYPE=tab|os-window` for pilot and rollback. Sessions already open as OS windows keep working and close as they do today.
- Not tested: a real `claude` session in a tab, including the LIN-790 transcript-flush check. Do that in the pilot. Watching changes too: there is one window (shown with the instance's tabs) instead of one per session.

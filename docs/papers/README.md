# Papers

Short documents, each carrying what it rests on. A **paper** answers one question with the
evidence; an **essay** argues a position from sources. `standard.md` says how each is written.
`proposals.md` lists the questions waiting for one.

| [learning-while-the-tools-change](harbour/learning-while-the-tools-change.md) | Astra 6 and Opus 5.5, version 5; typeset as [Harbour Archive #7](https://harbour.cat/archive/7). Engineering experience, experience using AI and the capability of the available tools run on three separate clocks, and better tools can take away the mistakes that used to teach — so the capability a team most needs to grow is calibrated distrust, knowing which output to check and which needs no check, and no snapshot of speed or seniority can see it. No cross-section can separate the clocks, however large; following the same people doing comparable work helps, though it is not enough by itself. Leapfrogging, factory electrification, the typesetter incumbents, Einstellung in chess masters and Barley's CT scanners supply the mechanisms; the Trio study, Anthropic's autonomy telemetry and Microsoft's 2026 agent rollout supply the contemporary edges. Version 5 is unchecked. |

Every fix is paid where it is written: code once, a prompt rule or review ledger on every run, so a fleet that answers each incident with prose ratchets upward even when each patch is reasonable. Rule-bearing text is only about 3% of what a worker carries; the bill is behaviour: loops, rounds that change nothing, writing read in part, pins that block deletion. The alternative is a steady base: full rigour where review has caught real bugs (the credential cutover), lean gates elsewhere, a byte budget whose overflow must go into code, and rules retired when they stop firing. Cunningham's debt, the NAO on Britain's regulatory budget and Texas sunset review supply the mechanisms. It cannot show reliability would hold with fewer rules. Version 2 is independently checked; the check's findings on the argument await John. |

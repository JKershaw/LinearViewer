It's to make runs reliable and legible, then just run a known-good default (DeepSeek / GPT) with Opus on review as the safety net, and read the real cost per feature. The finish line is a number: if a feature costs 20p, blast through the backlog; if it's £1, think harder. Get there without a model-selection research project.

The plan, in order

The sequence is the strategy. Harden before you measure (so the numbers aren't lies), measure before you commit (so “cheap” is a fact), run a default rather than optimise (the model will change anyway), and let the cost figure decide the rest. Model-tuning and the stepper are optimisations you earn, not gates you pass.

Why not just pick the best model now?

Because you'd spend real time and money choosing something that's obsolete next month — and you don't need to. Opus on review (already wired via LIN-1400) catches what a cheap build model gets wrong, so you get an honest result from any reliable default. The cost figure, not the model name, is what tells you whether to keep going. Optimise the model later, if the numbers say it's worth it.

02

What “done” means

Four checks, in the order you'll clear them. The last one is the actual goal — a number you can act on.

1 Reliable

An unattended run completes without wedging, failing silently, or losing its work — cheap model or not.

cleared by: Harden

2 Observable — in money

You can read a run's cost in £ and its wall-clock, per session. Not tokens you have to convert in your head.

cleared by: Observe (LIN-1287 + £-display)

3 Honest

Features ship on a cheap default for build with Opus on review, so mistakes are caught — quality without the spend.

cleared by: Run (LIN-1400, already wired)

4 Decidable ★

You have a real cost-per-feature figure — “feature X cost 20p” — that tells you whether to blast through the backlog or slow down.

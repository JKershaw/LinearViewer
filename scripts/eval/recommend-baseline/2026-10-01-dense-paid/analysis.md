## 1. Label corrections

The dense fixtures were built in beat 1 with `expected: ["implementation"]` for five
targets. That was a beat-1 label bug: the recommender's HEAD action vocabulary
(`getAIRecommendationActionNames()`, `lib/prompt-templates.js:457`) names the action
**`implement`**, and the existing fixtures accept `["implement", "implementation"]`.
The models correctly emit `implement`, so those five showed as misses purely on the
synonym. Fixed in `scripts/eval/fixtures/recommend/large-dense.json` (and its builder
`scripts/eval/build-large-dense-fixtures.mjs`, so regeneration stays consistent; the
`_source/` capture carries no labels):

| target | before | after | why |
|---|---|---|---|
| LIN-2149 | `["implementation"]` | `["implement","implementation"]` | convention fix |
| LIN-2944 | `["implementation"]` | `["implement","implementation"]` | convention fix |
| LIN-3098 | `["implementation"]` | `["implement","implementation"]` | convention fix |
| LIN-3135 | `["implementation"]` | `["implement","implementation","blocked"]` | convention fix **+ adjudication** |
| LIN-1892 | `["implementation"]` | `["implement","implementation","blocked"]` | convention fix **+ adjudication** |

Adjudications (decided from the ticket text, not from model votes):

- **LIN-3135** — `GET /api/proxy/issues/LIN-3135` at 2026-10-01: In Progress; PR #1616
  (R2, LinearViewer S1/S2/S4) merged after John's ruling, but the leg constraint says
  "S3 stays an explicit open item for the SD owner" and "LIN-3135 is **not** marked Done
  while it is open." **`close-out` is NOT defensible** — close-out owns merge + Done, the
  merge already happened and Done is explicitly withheld, so a close-out prompt is a
  no-op. **`blocked` is defensible** — the remaining work is named as owed by an external
  owner (the SD owner) and gates Done. Accepted set = `implement|implementation|blocked`.
- **LIN-1892** — In Progress; its own review ledger states "The ticket's Done is gated by
  **L5 and L6, which are post-deploy operator steps**" (production owner-population check,
  owner-index-in-prod, Resend key/sending-domain/`EMAIL_FROM`), i.e. a human gate. So
  `blocked` is defensible alongside the remaining S3 `implement` round. Accepted set =
  `implement|implementation|blocked`.

No other dense miss was widened: LIN-2149 (`breakdown` from 2 models) is not defensible
(the node already has an actionable child, so the honest action is defer), and the
`retrospective-audit` Done tickets stay pinned. `close-out`/`review`/`plan-review`
predictions on those are wrong, not label bugs.

  120_000` (`lib/openrouter.js:27`); proxy descent budget `LLM_TIMEOUT_MS = 180_000` /
  `RECOMMEND_DESCENT_BUDGET_MS = 180_000` (`routes/proxy.js:348,367`); context fetch
  `GRAPHQL_TIMEOUT_MS = 25_000` and `CONTEXT_FETCH_TIMEOUT_MS = 45_000`
  (`routes/proxy.js:337,358`) are separate from the LLM leg. Keepalive:
  `lib/http-keepalive.js` flushes `200` + a heartbeat at **25 s** and holds the socket

## 8. Recommendation

**Recommended model id: `qwen/qwen3.6-flash`** (paste into Settings → Workspace Settings →
Per-operation overrides → **Recommend**).

Deciding reasons:
- Highest production-fitness of every model tested — **85% overall / 87% small /
  80% dense**, with **zero** response-format errors (the only cheap candidate with none;
  gemini is disqualified by 11 format failures).
- **~9–11× cheaper than the incumbent** per call ($0.0098 vs $0.0896 all; $0.0187 vs
  $0.1985 dense) — the whole point of LIN-1693.
- Latency fits: p90 ≈22.7 s, under the 25 s keepalive trigger and the 120 s/180 s caps;
  context 1M ≫ 149k.
- Caveat stated plainly: on dense tickets the incumbent posts a higher point estimate
  (100% vs 80%, n=10–30, **within noise**). If dense reliability is judged paramount over
  cost, `openai/gpt-5.6-sol` remains the safe — but ~10× costlier — answer. On the
  measured overall distribution qwen beats the incumbent; per the ticket's cost goal,
  qwen is the recommendation.
- Rejected: `google/gemini-2.5-flash-lite` (format-unreliable), `openai/gpt-5.4-mini`
  (dense 60%, the known dense-degrader), `openai/gpt-5-mini` (slower, 2 prompt-quality
  failures, dense 67% vs qwen 80%).

**Exact paste target, re-verified at HEAD:** `preferences.aiModelOverrides.byKind.recommend.model`.
UI: Settings → Workspace Settings → the "Per-operation overrides (17)" collapsible
(`data-testid="ai-kind-overrides"`), row labelled **Recommend**; renders a preset
`<select>` **plus a free-text `custom model id` input** (`name="byKind__recommend__modelCustom"`)
— `lib/render-settings.js:349,361-369,391,406`. Form POSTs to
`/workspace/:urlKey/settings/ai-model-overrides` (`server.js:3728`), which accepts any id
matching `/^[a-z0-9-]+\/[a-z0-9.-]+(?::[a-z0-9-]+)?$/i`, custom field wins over the
select (`server.js:3731,3740-3742`), and stores it (`server.js:3751,3760-3764`).
**`qwen/qwen3.6-flash` matches the regex and is selectable as-is via the custom-id
input** — it is **not** in the curated `AVAILABLE_MODELS` dropdown, so the human must
type it, not pick it from the list. For a **free-tier** workspace the value is clamped
(`resolveFreeTierModel`) and would not take effect.
